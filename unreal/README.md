# Another World in Unreal

Unreal Engine 5.8 is the active direction for further world development. The Unity and JavaScript projects remain available as references for the gameplay migration.

Open `AnotherWorld/AnotherWorld.uproject`, or run `powershell -ExecutionPolicy Bypass -File unreal/Tools/open-project.ps1` from the repository root.

The native first-person game is launched with `Play.cmd`, or `powershell -ExecutionPolicy Bypass -File unreal/Tools/play-game.ps1`. Its default is `/Game/Maps/HidrokFuture`, the initial Unity-inspired advanced-civilization pass. Use `-Map HidrokPlayable` to inspect the earlier period streetscape. Controls: WASD move, mouse look, Shift sprint, Space jump, hold C crouch, F flashlight. The chest-height camera has restrained movement and a small sprint FOV change; there is no weapon or character body model yet. Collision blocks the 177 building footprints because their interiors have not been migrated.

The futuristic map replaces period architecture with layered pearl ceramic, graphite recesses, panoramic glazing and cyan service bands on all 177 preserved plots. Twelve nearby plots have extra facade/roof detail, including two glass pavilions. Low planters, pavement inlays, a cross-street elevated guideway, operating Orion services and playable Aurora X9 cars, and a shallow transparent hexagonal canopy establish the Unity identity. The canopy uses Unity's 1700 m radius / 480 m height. Orion regional trains run underground and trams use the elevated guideway. T uses signed station lifts; E boards or alights at Central when stopped with doors open. See ORION-TRANSIT.md. The shield remains a visual prototype. Everyday cars include Aurora X9, Skyline X7 and Aerodynex X12 (see TRANSPORT-VARIANTS.md): E enters/exits, WASD drives, Shift boosts, F deploys flight mode or requests landing, Space/Q climbs/descends, L toggles landing gear and C switches cameras. Land and fold the wings before exiting. This is procedural environment design, not a claim of photographic fidelity. See `FUTURE-DIRECTION.md` for the actual reviewed reference sources and gaps.

Regenerate with `Tools/build-future-district.ps1` after preparing `HidrokPlayable`. This replaces only the generated `HidrokFuture` map and its generated `/Game/Future` materials. Run `Tools/verify-game.ps1 -Map HidrokFuture` for the real-map movement check and a native in-game screenshot at `AnotherWorld/Saved/Screenshots/WindowsEditor/HidrokFuture.png`. Two rendered passes were inspected; the second moved the obstructive central guideway across the intersection and set the hover prototypes back. A matched 150-frame profiling capture identified Temporal Super Resolution as the main bottleneck on Intel HD 530 (about 150 ms/frame). Replacing TSR with FXAA changed mean frame time from 176.8 ms to 25.5 ms, about 6 to 39 FPS in that short scene sample. See SourceData/profile-baseline.json and profile-fxaa.json; with Aurora cars loaded, a further sample averaged 30.8 ms (about 33 FPS), recorded in SourceData/profile-aurora.json. These short samples are not a whole-game performance guarantee.

The gameplay source is C++ under `AnotherWorld/Source/AnotherWorld`. Build it with `Tools/build-game.ps1`, then generate the walking map with `Tools/prepare-playable-city.ps1`. The build requires Visual Studio C++ Build Tools, a Windows SDK and .NET Framework SDK 4.6 or newer. On this workstation the missing .NET Framework 4.8 SDK is extracted locally under the ignored `Toolchain` folder; `Tools/setup-local-sdk.ps1` recreates it from checksum-verified Microsoft payloads. Unreal's legacy AutoSDK lookup uses a 4.6.2 compatibility path for those actual 4.8 files; the build wrapper sets this only for its process. No registry or machine SDK modifications are required.

`Tools/verify-game.ps1` runs the native walking check in the real map, checking grounded spawn, collision at every building footprint, walking, sprint distance, jump and landing. It saves an in-game screenshot and automation report under `AnotherWorld/Saved`. It is a smoke check rather than a frame-rate benchmark. Regenerating the walking map replaces that derived map; preserve any manual edits first.

The walking map retains all 39,700 authored instances in 108 hierarchical clusters, with a 180 m maximum architecture cull distance. Street props are currently decorative and do not have detailed player collision. An explicit non-colliding sky actor prevents the sky sphere from ejecting the character at spawn. Ground and pavement collision is enabled explicitly, with a solid support floor below Ashford. Imported material-instance usage flags are persisted for in-game instanced rendering by `prepare_runtime_materials.py`.

`play-game.ps1` defaults to a launch-only DX11 compatibility profile at 85% internal resolution with FXAA with reduced effects and shadow distance for the Intel HD 530. Pass `-FullQuality` to omit those scalability overrides. The functional check uses a 3 FPS startup guard so that collision tests are not gated on a 10 FPS performance target; passing it does not establish smooth gameplay. Pass `-Headless` for physics-only diagnostics, followed by the rendered check for appearance.

On this workstation use the launch script: it selects DirectX 11 for preview after DirectX 12 failed allocating the editor primitive render target. This is a compatibility preview; advanced DX12 features are unavailable. Pass `-GraphicsApi d3d12` to test DX12 later. The script does not change the project's final rendering target. Launch from a normal desktop PowerShell so Unreal's .NET helpers can write their AppData logs.

The startup map is `/Game/Maps/HidrokFuture`. The earlier playable map remains `/Game/Maps/HidrokPlayable`, its authored art source remains `/Game/Maps/HidrokAuthoredStreet`, and the preserved website migration map is `/Game/Maps/HidrokWebsite`. Its first slice imports Ashford's original base construction directly from `main.js`: 177 generated buildings, their actual transforms, road/pavement geometry and destination markers. Website metres become Unreal centimetres, with Y-up converted to Z-up. The original migration keeps its nine canvas textures; the authored map uses the imported models described below.

Other cities, later civic landmarks, home interiors, NPCs, traffic, powers and interactions are pending. In the preserved website snapshot, custom meshes are omitted; primitive spheres/cones/cylinders are approximations. Transparency, normal maps and separate face materials are pending in that snapshot. The native walking map adds a first-person controller and coarse building-footprint collision; it does not reproduce every website traversal rule. Import runs without rendering and does not verify appearance or frame rate.

Those geometry/material omissions describe the original website snapshot. `HidrokAuthoredStreet` replaces all 177 generic building exteriors with Poly Haven's authored apartment and factory façade modules, including their trim, window and door geometry, UVs and PBR materials. Original building centres remain unchanged. Worn benches, bins, refuse bags, wall lanterns, manhole covers, gutter grilles and storefront signs dress the city. Movable daylight and the existing photographic HDR sky light the scene. Interior room cores and floor plates remain simple geometry.

About 45 MiB of selected CC0 source models and 1K textures are retained under `SourceAssets`; exact file URLs, hashes and license records are in `SourceAssets/CREDITS.json`. `prepare-street-kits.cjs` selects named modules and removes the source files' presentation-grid transforms while preserving original downloads. Imported meshes/textures live under `/Game/AuthoredStreet`. Repeated geometry is serialized in spatially grouped native instance components; architecture is culled beyond 300 m and street details beyond 150 m. These distances and the 1K texture ceiling are preview choices, not a frame-rate guarantee.

The authored Ashford build has 39,700 instances in 108 batches. Save/reload checks confirm the source footprints, materials and static component ownership, and the actual DX11 street screenshot has been inspected. Results are in `SourceData/authored-street-report.json` and `SourceData/authored-street-verification.json`. This is an environment art pass; the scene is not claimed to match Bodycam's fidelity and the other four cities still need porting.

To rebuild from downloaded source: run `node unreal/Tools/prepare-street-kits.cjs`, execute `import_street_kits.py` through the Unreal Python commandlet if imported assets are missing, then run `powershell -ExecutionPolicy Bypass -File unreal/Tools/build-authored-street.ps1`. The build wrapper also reloads the saved map and checks the source footprints, instance counts, materials and light mobility. `powershell -ExecutionPolicy Bypass -File unreal/Tools/review-street.ps1` captures the actual DX11 viewport under `AnotherWorld/Saved/Screenshots/HidrokAuthoredStreet.png`. It does not constitute a full hardware benchmark. Build scripts replace generated maps, so preserve manual map edits first.

With the website server running on port 8080, run `node unreal/Tools/export-web-world.cjs`, then `powershell -ExecutionPolicy Bypass -File unreal/Tools/import-web-world.ps1`. The exporter executes the original Ashford construction boundary, excluding later population/simulation code. Generated source data and the import report are in `SourceData`. Re-importing replaces only `HidrokWebsite`, so preserve manual edits first. New art should live in separate assets/maps rather than generated source data.

The earlier `/Game/Maps/CityBlock` starter is retained separately. It is not the website city.

`/Game/Maps/HidrokStreet` is the first street art pass derived from the migration map. Six source building footprints have masonry modules, inset glazing, frames, sills, entrance assemblies, parapets and downpipes. Photographed local CC0 diffuse, normal and roughness maps replace surfaces in this pass; their existing attribution is copied to `SourceData/surface-credits.json`. Movable sunlight and the existing HDR sky avoid an unbuilt static-lighting dependency. These are procedural modules, not scanned buildings, and the result is not claimed to match Bodycam.

Regenerate with `Tools/upgrade-street.ps1`; this replaces the generated street map. `Tools/review_street.py` runs inside the graphical DirectX 11 editor and captures a real screenshot under `AnotherWorld/Saved/Screenshots/StreetReviewFinal.png`. Null-renderer generation cannot establish visual quality. The preview GPU reported by Unreal is Intel HD Graphics 530; this compatibility preview does not use Lumen and is not a benchmark for a higher-end rendering target.

`Tools/build_world.py` creates and saves the map and shared materials through Unreal's editor Python plugin. Re-running it replaces the starter map, so preserve any manual map edits first.

Generate with `powershell -ExecutionPolicy Bypass -File unreal/Tools/build-world.ps1`. The tools use a workspace-local file cache to avoid the unavailable shared Zen cache. Generation runs without rendering; a successful run does not verify lighting, appearance or gameplay.

The fleet now uses full-size rolling/steering road wheels with independent parking stabilisers. P deploys pads while parked; B opens the rear luggage boot, H the separate forward service bonnet, O the cabin doors, and K the diagnostics panel. The boot includes release delay, visible struts, latch/lock state and a game obstruction-reversal check. See VEHICLE-SERVICE.md for the mechanical layout, technician inspection workflow, implementation limits and unfinished engineering.

Orion now runs an underground eight-section regional train and an elevated four-section tram. T uses the signed station lifts; E boards/alights at Central with doors open. Both routes include controlled acceleration, braking, turnbacks and platform gates. See ORION-TRANSIT.md for the one-station-per-route and instant-lift limits. The Orion surface-scene profile averaged 35.1 ms (about 29 FPS), with a 62.2 ms 95th-percentile frame time on Intel HD 530; this is a short compatibility capture, not a whole-route benchmark.
